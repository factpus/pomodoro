# Pomodoro Together 改善記録

最終更新: 2026-08-20

## 目的

単独利用しかできなかったタイマーを、複数人が同じルームで正確かつ安全に利用できるポートフォリオ品質のWebアプリへ改善する。

## 原因と判断

旧実装は、Vercelでは起動されない常駐Node/Socket.IOサーバーとプロセスメモリに依存していました。そのため画面は共有アプリを名乗っていても、実際には端末ごとのLocal modeへフォールバックしていました。また、1秒ずつ値を減算する方式はタブ休止や切断で時刻がずれます。

Vercelの500エラー自体はFramework Presetが `Other` だったことが直接原因で、Next.jsへ修正済みです。複数人利用不能はVercelの障害ではなく、Vercelの実行モデルとアプリ構成の不一致でした。

## 完了した修正

- Socket.IOと旧常駐サーバーを撤去
- Redisを共有状態の正とするAPIを実装
- `phaseEndsAt` とサーバー時刻による正確な状態モデルへ変更
- 切断時のローカル分岐を廃止し、自動再接続・復元を実装
- ホストトークンと参加者の読み取り専用権限を実装
- Zod入力検証、IPレート制限、分散ロックを実装
- ルーム24時間TTLと参加者15秒TTLを実装
- 招待URL、参加人数、プリセット、長休憩、通知を実装
- UIを日本語へ統一し、重複表示、タッチ操作、ラベル、モバイル表示を改善
- 約80MBのWAVを約7MBのMP3へ圧縮し、操作時読み込みへ変更
- About、OG画像、PWA manifest/service workerを追加
- Vitest単体テスト、Playwright 2クライアントE2E、GitHub Actionsを追加
- READMEとアーキテクチャ文書を更新

## 本番リリースの最終条件

- Vercel MarketplaceでUpstash Redisを作成し、`pomodoro-app` に接続する
- mainへpushして本番デプロイを実行する
- 異なる2ブラウザで、作成・参加・開始・停止・再接続を確認する

Redis未接続の本番では、誤って不完全な共有モードを提供しないようAPIが503を返します。

## 自動検証の対象

- 開始、一時停止、リセット、フェーズ遷移、完了回数、長休憩
- 不正なルーム名と時間設定の拒否
- 2クライアントの状態同期
- ホスト権限と参加者の操作禁止
- オフライン後の再接続と状態復元
- lint、TypeScript、本番ビルド、依存関係監査
