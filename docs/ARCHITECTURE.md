# アーキテクチャ

最終更新: 2026-08-22

## 状態同期

Vercel Functionsは常駐プロセスを保証しないため、Socket.IOサーバーとプロセスメモリを共有状態の正として使いません。表示状態は1秒のCDNキャッシュを持つ公開スナップショットAPIから2秒間隔で取得し、参加状態とホスト権限は10秒間隔のheartbeatで更新します。非表示タブでは公開ポーリングを止め、復帰時に即時同期します。複数利用者の読み取りをCDNで集約しつつ、通常2秒以内の反映を維持します。

Redisに保存するタイマー状態には `phaseEndsAt`、`pausedRemainingSeconds`、`version`、各時間設定、完了回数を含めます。稼働中の残り時間はカウンターではなく `phaseEndsAt - serverNow` から算出するため、バックグラウンドタブや一時切断でドリフトしません。

## 整合性

更新処理はルーム単位のRedis分散ロック内で行います。ルームには24時間のTTL、参加者には15秒の生存期限があります。読み取り時にも経過済みフェーズをサーバー時刻で進めるため、常駐タイマー処理は不要です。

## 権限と入力

作成時に256-bitのホストトークンを発行し、ブラウザのsessionStorageへ保存します。サーバーにはSHA-256ハッシュだけを保存し、比較はタイミング攻撃に配慮して行います。招待URLにはトークンを含めません。

Discordコマンドから作成する場合は、実行者だけに見える応答のURLフラグメントでホストトークンを一度だけ渡します。ブラウザは保存後すぐURLから除去します。Discord Webhook URLはAES-256-GCMで暗号化し、疎通確認に成功した場合だけ保存します。

ルーム名、時間設定、クライアントID、操作コマンドはZodで検証します。作成・読み取り・生存確認・操作にはIP単位のレート制限があります。

## 障害時

共有ルームでは切断中にローカル状態へ分岐せず、操作を止めて「再接続中」と表示します。復帰時にRedisの状態を取得して自動復元します。Redisがない本番環境では、共有できるように見せかけず503を返します。

## 連携境界

Discord Webhookの送信失敗はタイマー操作から分離し、共有状態を停止させません。Discord InteractionはEd25519署名を検証します。Embedded App SDKはDiscord iframe内かつ設定済みの場合だけ初期化し、通常ブラウザでは読み込みません。CSPはDiscordからの埋め込みを許可しながら、その他のframe ancestorと不要な端末権限を制限します。

## 将来の拡張

同期方式はクライアントAPI層に分離しています。利用規模が大きくなりポーリングのコストが問題になった場合、状態モデルや権限モデルを保ったままSSE、WebSocket、マネージドRealtimeへ置き換えられます。
