# Pomodoro Together 広告収益化調査

最終更新: 2026-08-21

## この資料の目的

Pomodoro Togetherを一つの公式Webサービスとして運営し、無料利用を維持しながら広告収入で運営費と開発費を回収するために必要な条件、リスク、実装、法務、計測、集客を整理する。

Google AdSenseを最初の広告配信候補とするが、AdSenseだけに依存せず、利用規模が小さい段階では直接スポンサー広告も比較対象に含める。

この資料は事業・実装判断のための調査であり、法的な助言ではない。広告公開前に、実際のデータ送信内容と運営形態を前提として専門家へ確認する。

## 結論

広告モデルは、Pomodoro Togetherの「全員が同じ公式URLへ集まる」という価値と整合する。顧客ごとに同一アプリを複製するセルフホスト販売より、公式サービスへ利用者、改善、ブランドを集中できる。

ただし、現在のアプリへ広告コードを追加するだけでは成功しにくい。先に次の四つを満たす必要がある。

1. 独自ドメインと、審査対象になる十分な独自コンテンツを用意する
2. タイマー操作を邪魔せず誤クリックを生まない広告位置を設計する
3. Cookie、個人関連情報、外部送信、国外利用者への同意管理を整備する
4. 1秒ポーリングを見直し、広告1表示あたりのインフラ費用を下げる

推奨する開始形は次のとおり。

- タイマーの基本機能は完全無料
- 集中中の画面を広告で覆わない
- トップ、使い方・解説記事、手動で開くセッション結果画面を収益化
- ルーム画面へ置く場合は、操作領域から十分離れた広告を1枠だけ、ページ読込時に1回表示
- Discord Activity内では当面AdSenseを表示しない
- 月間利用が小さい間は、Cookieを使わない固定スポンサー枠も検討

## 広告モデルへ変更する理由

### プロダクト構造との相性

- 共有URLへ参加者が集まること自体が価値になる
- 公式サービスを一か所で更新できる
- Discord・LINEで共有されたリンクが同じブランドへ流入する
- 参加者は購入判断や環境構築をせずに利用できる
- 作者が公式版、品質、表示、データ取扱いを直接管理できる

### セルフホスト販売との違い

セルフホストは、組織固有のデータ、認証、規制、閉域環境、業務フローが必要な場合に意味がある。一方、一般向け共同タイマーでは、同じ機能を持つ複数のURLが並立すると、参加方法、更新状況、信頼性、ブランドが分散する。

セルフホスト販売資料は検討記録として残すが、現時点の主戦略にはしない。

## 最初の広告配信候補

### Google AdSense

利点:

- 小規模なWebサイトでも申請できる
- 広告主を個別開拓せず開始できる
- 自動広告と手動広告ユニットを選べる
- ページ、広告ユニット、国などの実績を管理画面で確認できる

注意点:

- サイト全体の審査がある
- 独自性・十分なコンテンツ・明確なナビゲーションが必要
- 低価値またはコンテンツのない画面への広告は禁止
- 操作ボタン付近の広告や誤クリックを招く配置は禁止
- 自動リロードによる広告更新は禁止
- 無効な表示・クリックはアカウント停止につながり得る
- プライバシーポリシーと地域別の同意管理が必要

Googleは、申請サイトに独自で興味深いコンテンツがあり、ポリシーを満たし、申請者がHTMLを編集できることなどを求めている。

- [AdSense利用資格](https://support.google.com/adsense/answer/9724?hl=ja)
- [AdSense審査前のサイト準備](https://support.google.com/adsense/answer/7299563?hl=ja)
- [サイトをAdSenseへ接続する手順](https://support.google.com/adsense/answer/7584263?hl=ja)

### 直接スポンサー広告

作者が、学習サービス、コワーキングスペース、生産性ツール、Discordコミュニティなどと直接契約し、固定の画像またはテキスト枠を掲載する方式。

利点:

- 広告ネットワークの入札単価に依存しない
- 月間PVが少なくても、対象利用者との相性を価値として提案できる
- 自社配信の静的画像と通常リンクだけなら、第三者広告タグよりデータ送信を減らせる
- 集中体験に合う広告主だけを選べる

注意点:

- 広告主の開拓、契約、請求が必要
- PR表記、掲載期間、表示回数、競合排除、素材審査を決める必要がある
- クリック計測を行う場合は、送信情報と利用目的を開示する必要がある

初期段階では、AdSense審査の準備を進めながら「このサービスは○○の提供で運営されています」という1社限定のスポンサー枠を併設できる。

## AdSense審査に対する現在地

### 満たしている点

- 作者がNext.jsのHTMLとコードを編集できる
- 公開済みでHTTPS接続できる
- 日本語はAdSenseの対応言語
- Aboutページがある
- アプリとして独自の共同同期機能がある
- モバイル表示、PWA、基本ナビゲーションがある

### 不足している点

- 現在のトップページはルーム作成フォームが中心で、文章コンテンツが少ない
- Aboutページも短く、サイト全体として情報量が少ない
- プライバシーポリシーがない
- Cookie・外部送信に関する説明がない
- 利用規約、問い合わせ先、運営者情報がない
- 広告審査とブランド確立に適した独自ドメインがない
- 広告配置専用コンポーネントと同意状態管理がない
- 広告を表示してよいページと除外するページの方針がない
- `ads.txt`がない

Googleは、文字情報が少ない、未完成、独自で豊かな内容が不足している、ナビゲーションが不明瞭と判断したサイトを承認しない場合がある。現在のAboutページだけでは審査対策として弱い。

- [AdSenseアカウントが承認されない場合](https://support.google.com/adsense/answer/81904?hl=ja)

### 独自ドメイン

AdSenseのサイト登録は、標準ドメインまたは認められたPublic Suffix上のサイトを対象とし、通常のサブドメインを自由に登録する方式ではない。現在の`vercel.app` URLが管理画面で登録可能かに依存せず、事業用には独自ドメインを取得する。

- [AdSenseへ入力できるURL](https://support.google.com/adsense/answer/2784438?hl=ja)

独自ドメインにする理由:

- 作者が管理する正規サイトを明確にできる
- AdSenseのサイト所有確認を行いやすい
- ルートに`ads.txt`を置ける
- Vercelプロジェクト名が変わってもURLを維持できる
- Discord・LINE共有、検索、名刺、ココナラ実績のURLを統一できる

候補名を決める際は、ドメイン取得可否だけでなく、既存サービス名と商標の衝突を確認する。

## 広告を表示するページ

### 推奨配置

| 画面 | 方針 | 理由 |
| --- | --- | --- |
| トップ | 1枠。説明コンテンツの後 | 作成・参加ボタンとの誤クリックを避ける |
| 使い方・記事 | 本文中または末尾に1～2枠 | 独自コンテンツと広告の関係が明確 |
| FAQ・About | 末尾に1枠 | 情報を読んだ後に限定 |
| ルーム待機中 | 原則1枠まで | 操作領域から十分離す |
| 集中中 | 非表示を第一候補 | 注意を散らさず、画面外注目広告を避ける |
| 休憩中 | 小さな1枠を検証可能 | ただし自動更新はしない |
| 手動終了後の結果 | 1枠 | 明確な結果コンテンツと組み合わせる |
| 404・接続エラー | 非表示 | 警告・ナビゲーション用途の画面だから |
| Discord Activity | 当面非表示 | 音声チャット内・iframe・画面外注目のポリシーリスク |

Googleは、コンテンツのない画面、低価値画面、警告やナビゲーションなど行動目的だけの画面、広告がコンテンツより多い画面への広告を認めていない。

- [Google Publisher Policies](https://support.google.com/adsense/answer/10502938?hl=ja)
- [コンテンツより広告が多い画面に関するポリシー](https://support.google.com/publisherpolicies/answer/11169917?hl=ja)

### タイマー画面での誤クリック対策

広告は次の要素から視覚的・物理的に離す。

- 開始・一時停止ボタン
- リセット・スキップボタン
- 音量操作
- 招待・共有ボタン
- 通知許可ボタン
- モバイル画面下部の親指が届く操作領域

広告を「おすすめ」「次へ」「支援する」など、操作や作者支援と誤認する見出しの下へ置かない。自分や知人へ広告クリックを依頼しない。

- [AdSense広告配置ポリシー](https://support.google.com/adsense/answer/1346295?hl=ja)
- [無効なトラフィックによる停止](https://support.google.com/adsense/answer/2659114?hl=ja)

### 自動広告は審査後も慎重に使う

Auto adsはページ構造を解析して配置するが、タイマー操作の近く、オーバーレイ、アンカー広告などが集中体験と衝突する可能性がある。

最初は手動広告ユニットを使い、次を固定する。

- 置ける領域をコード側で限定
- ルーム、エラー、Discord Activityなどをページ除外
- オーバーレイ形式を無効化
- モバイルとデスクトップを個別確認
- Core Web Vitalsと操作ミスを計測

Auto adsを試す場合はプレビューと実験機能を使い、全面適用しない。

- [Auto adsの設定](https://support.google.com/adsense/answer/9261307?hl=ja)

## 最重要の採算問題: 1表示と1,800 APIリクエスト

現在のルーム画面は、各クライアントが次の通信を行う。

- ルーム状態取得: 1秒に1回
- heartbeat: 5秒に1回
- 25分間の状態取得: 約1,500回
- 25分間のheartbeat: 約300回
- 合計: 1人・1セッションあたり約1,800 APIリクエスト

ブラウザ内の残り時間表示は250msごとに更新されるが、これはローカル処理なのでAPI回数には含まない。

AdSenseでは、利用者の操作なしにページや広告要素を自動更新できない。そのため、25分間開き続けても広告表示を1分ごとに増やすことはできない。

- [AdSenseの自動更新禁止](https://support.google.com/adsense/answer/1346295?hl=ja#Auto-refreshing_ads)

### このまま利用者が増えた場合

10人が25分使う1ルームでは、概算18,000 APIリクエストに対して、ページ読込時の広告表示は約10回になる。広告1表示が支えるAPI回数が多く、Vercel FunctionsとRedisの費用が広告収益より先に増える可能性がある。

### 広告導入前に行う最適化

1. 残り時間は現在どおり`phaseEndsAt`と端末時計からローカル計算
2. 通常同期を1秒から5～10秒へ変更
3. heartbeatと通常同期を可能な範囲で統合
4. 操作直後、オンライン復帰、タブ再表示時だけ即時同期
5. 非表示タブでは同期間隔を延長
6. フェーズ終了予定時刻には即時再取得
7. 同期精度、参加人数TTL、再接続をE2Eで再検証
8. 規模拡大後はSSEまたはマネージドRealtimeを比較

10秒に1回の統合同期へ変更できれば、25分で約150回となり、現在から約12分の1に削減できる。これは実装前の概算であり、参加者TTLやフェーズ切替精度を確認して決定する。

## 現在のホスティング費用と商用利用条件

### 独自ドメイン自体はVercel Proを要求しない

Vercel Hobbyでもカスタムドメインを設定でき、公式の制限表では1プロジェクトあたり50ドメインまで対応している。したがって、独自ドメイン設定だけを理由にProへ移行する必要はない。必要になるのはドメイン登録事業者へ支払う取得・更新費用である。

- [Vercel Limits](https://vercel.com/docs/limits)
- [Vercelカスタムドメイン設定](https://vercel.com/docs/domains/set-up-custom-domain)

### 広告とスキン販売はVercel上の商用利用になる

Vercel Hobbyは非商用の個人利用に限定されている。公式Fair Use Guidelinesは、Google AdSenseなどの広告掲載、支払いの処理、商品・サービス販売の広告を商用利用の例として明記している。広告または有料スキンを本番導入する場合、Vercelを継続するならPro以上へ移行する。

2026-08-22時点でVercel Proは月額20ドルで、20ドル分の利用クレジットを含む。為替、税、超過利用により実際の円建て負担は変動する。

- [Vercel Fair Use Guidelines](https://vercel.com/docs/limits/fair-use-guidelines)
- [Vercel Pricing](https://vercel.com/pricing)

### ポートフォリオ運用

広告、課金、商品販売を行わず、制作物のデモとして公開するだけなら、Hobbyで運営を続けられる可能性が高い。ただし、サイト自体で有料サービスを宣伝するなど、金銭的利益を目的とする使い方へ変える場合はVercelの商用利用定義を再確認する。

### Upstash Redis

2026-08-22時点のUpstash Redis Freeは月500,000コマンド、Pay as You Goは100,000コマンドあたり0.20ドルである。

- [Upstash Redis Pricing](https://upstash.com/pricing/redis)

現在の25分セッションを1人が利用した場合の概算は次のとおり。

| 処理 | 回数 | 主なRedisコマンド概算 |
| --- | ---: | ---: |
| 1秒ごとのGET | 1,500回 | rate limit `INCR`、room `GET`など約3,025 |
| 5秒ごとのheartbeat | 300回 | rate limit、lock、room read/write、unlockなど約1,825 |
| 合計 | 1,800 API | 約4,850 Redisコマンド |

これはコード経路から求めた概算で、競合ロックの再試行、ルーム操作、Upstash側の計上方法により変動する。単純計算では、Freeの500,000コマンドは月約100人・25分セッションで到達し得る。実際のUpstash管理画面のコマンド数を計測して補正する必要がある。

Pay as You Goでは、現在の同期方式による25分・1人分のRedisコマンド費は概算0.0097ドルとなる。1回は小額でも、広告は原則1ページ表示なので、大量利用時には広告収益よりRedis費が速く増える可能性がある。

## 収益化を急がない選択肢

現段階で最も損失が小さく、将来の選択肢を残せる方針は「ポートフォリオとして無料運営し、実利用が増えてから収益化する」ことである。

### Portfolio First

1. Vercel HobbyとUpstash Freeで非商用公開を継続
2. 独自ドメインはブランド・AdSense準備として任意取得
3. 同期通信を最適化し、無料枠で収容できる利用数を増やす
4. 個人追跡を抑えた集計で、月間PV、セッション数、再訪率を測る
5. 広告なしの状態でDiscord・LINE連携とポートフォリオ価値を完成させる
6. 実績値を基に、AdSense、固定スポンサー、スキン販売を再評価

### 広告開始の仮ゲート

広告開始前に、少なくとも次を満たしていることを確認する。

- 月間PVと再訪が3か月程度継続して増加
- AdSense審査用の独自コンテンツと法的表示が完成
- 適応同期により1セッションあたりのインフラ使用量を把握
- 想定広告収益がVercel Pro、Redis、ドメイン費を上回る
- 広告導入後も運営継続する価値がある利益または集客効果を見込める

仮にページRPMを300円、Vercel Proを月約3,000円相当と置くと、Vercelだけの損益分岐は約10,000PVとなる。しかしRedis、ドメイン、税、広告未表示、保守時間を含めると利益はほぼ残らない。開始判断は月30,000PV前後など、固定費を明確に上回る実績が見えてから行う方が安全である。PV基準は実際のRPMと費用で更新する。

### ポートフォリオの間接的な収益

広告を掲載しなくても、このアプリは次の能力を証明する成果物になる。

- Vercelの実行モデルを踏まえた障害診断
- Socket.IO依存からサーバーレス対応構成への移行
- Redis共有状態、分散ロック、権限、レート制限
- 複数ブラウザ同期、再接続、時刻ドリフト対策
- Next.js、PWA、CI、単体・E2Eテスト
- Discord・LINE連携とプロダクト設計

この価値はアプリから直接広告収入を得るのではなく、ココナラやフリーランス案件で「同種の問題を解決できる作者」として受注へつなげるものになる。公式アプリの複製販売をしなくても、技術と開発サービスを販売できる。

## 収益を計算する方法

Googleが示すRPMは、推定収益をページビュー、表示回数などで割って1,000倍した指標である。

```text
ページRPM = 推定収益 ÷ ページビュー × 1,000
推定収益 = ページビュー ÷ 1,000 × ページRPM
```

- [Google「Revenue per thousand impressions」](https://support.google.com/adsense/answer/190515?hl=ja)

### 感度分析

実際のRPMは、国、季節、広告分野、端末、広告位置、同意率などで変わる。以下は実績予測ではなく、必要PVを理解するための仮定である。

| 月間PV | RPM 100円 | RPM 300円 | RPM 500円 |
| ---: | ---: | ---: | ---: |
| 10,000 | 1,000円 | 3,000円 | 5,000円 |
| 50,000 | 5,000円 | 15,000円 | 25,000円 |
| 100,000 | 10,000円 | 30,000円 | 50,000円 |
| 500,000 | 50,000円 | 150,000円 | 250,000円 |

日本円のAdSense支払基準額は8,000円。RPMを仮に300円とすると、累計約26,667PVで8,000円へ到達する計算になる。これは単純計算で、無効トラフィック調整、広告未表示、為替、税務などを含まない。

- [AdSenseの支払基準額](https://support.google.com/adsense/answer/1709871?hl=ja)

### このアプリで「PV」を増やす方法

タイマーを長時間開かせても、自動広告更新は禁止されているため収益は比例しない。必要なのは不自然な画面更新ではなく、次の正当な閲覧機会である。

- 検索から使い方・解説記事へ来る
- トップからルームを作る
- Discord・LINE共有から参加者が来る
- 利用者が手動でセッション結果を開く
- 翌日また利用する
- 技術記事からアプリを試す

ルーム参加者数、再訪日数、自然なコンテンツ閲覧を伸ばすことが広告収益につながる。

## 計測する指標

### プロダクト指標

- 日間・月間の利用端末数
- ルーム作成数
- ルーム参加者数
- 1ルームあたり参加人数
- 集中セッション開始数・完了数
- Discord・LINE共有数
- 翌日・翌週の再訪率
- 接続エラー率
- 1セッションあたりAPI・Redisリクエスト数

### 広告指標

- 広告対象ページのPV
- 広告表示回数
- 広告が実際に表示可能だった割合
- ページRPM・広告RPM
- 国・端末・ページ別収益
- 広告ブロッカー等による未表示
- 広告導入前後の離脱率とセッション開始率
- Core Web Vitals

広告クリック率を上げるために配置を操作するのではなく、誤クリックが増えていないことを監視する。異常な表示・クリックを見つけた場合は、原因調査まで広告を停止できる仕組みを用意する。

### 最小限の分析から始める

初期段階では、個人を追跡する詳細分析より、日単位の集計を優先する。

- ルームID、ホストトークン、DiscordユーザーIDを広告分析へ送らない
- URLパスからルームIDを除外または置換して計測する
- タイマー名など利用者入力を広告・分析事業者へ送らない
- IPアドレスを独自に長期保存しない
- 保存期間を決める

## プライバシー、Cookie、外部送信

### Googleの必須事項

AdSenseは広告配信・計測などにCookieを使用する。Googleは、すべてのパブリッシャーへCookie利用を明示するプライバシーポリシーを求めている。

- [AdSenseによるCookieの使用](https://support.google.com/adsense/answer/7549925?hl=ja)
- [プライバシーポリシーへ必要な内容](https://support.google.com/adsense/answer/1348695?hl=ja)

プライバシーポリシーには少なくとも次を含める。

- 運営者
- 取得・保存する情報
- Googleなど第三者広告事業者によるCookie利用
- 過去の閲覧情報等に基づく広告が表示される可能性
- 広告パーソナライズを無効化する方法
- 利用目的
- 保存期間
- 第三者提供・国外送信
- 問い合わせ・削除依頼
- ポリシー変更

### 日本

個人情報保護委員会は、Cookieなどの端末識別子が、個人情報に該当しない場合でも通常は「個人関連情報」に該当すると説明している。

- [個人情報保護委員会「Cookie等の端末識別子」](https://www.ppc.go.jp/all_faq_index/faq1-q8-1/)
- [個人情報保護法ガイドライン](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/)

また、運営形態が電気通信事業法の外部送信規律の対象になる場合、広告タグなどにより利用者情報を外部へ送信するとき、送信情報、送信先、利用目的について通知、公表、同意取得、オプトアウトなどによる確認機会が必要になる。対象事業者該当性はサービスの実態によるため、広告公開前に確認する。

- [総務省「外部送信規律FAQ」](https://www.soumu.go.jp/main_sosiki/joho_tsusin/d_syohi/gaibusoushin_kiritsu_00002.html)

実装上は、適用の最低線だけを狙わず、フッターから1クリックで到達できる「外部送信について」ページへ次を表形式で掲載する。

| 送信先 | 送信情報 | 利用目的 | 停止方法 |
| --- | --- | --- | --- |
| Google LLC | Cookie、端末・ブラウザ情報、閲覧URL、広告表示・操作情報等 | 広告配信、測定、不正防止 | 同意設定、Google広告設定等 |

実際の記載内容は、採用するAdSense設定、CMP、アクセス解析を確認して確定する。

### EEA、英国、スイス

これら地域へ広告を配信する場合、Googleは、パーソナライズ広告についてGoogle認定CMPとIAB TCFへの対応を求めている。AdSenseの「プライバシーとメッセージ」からGoogle CMPを利用する方法を第一候補とする。

- [Google認定CMP要件](https://support.google.com/adsense/answer/13554116?hl=ja)
- [AdSense CMP設定](https://support.google.com/adsense/answer/7670013?hl=ja)

最初から海外アクセスを技術的に排除しないなら、申請時点でCMPを用意する。対象地域では同意前に広告タグや関連Cookieを不用意に動かさない。

## 技術実装の構成

### 環境変数

```text
NEXT_PUBLIC_ADSENSE_CLIENT_ID=ca-pub-xxxxxxxxxxxxxxxx
NEXT_PUBLIC_ADS_ENABLED=false
NEXT_PUBLIC_CONSENT_MODE=...
```

広告IDをGitへ直接書かず、プレビュー・E2E・ローカル環境では広告を無効化する。本番でも審査前は`ADS_ENABLED=false`にする。

### Next.js側の実装候補

- ルートレイアウトの`head`へAdSense確認用metaまたは公式scriptを追加
- `next/script`で読み込み戦略を明示
- 広告ユニットを`AdSlot`コンポーネントへ隔離
- 許可ページと除外ページを中央設定で管理
- 同意状態が整うまで必要な広告処理を開始しない
- 広告領域の高さを予約し、表示時のレイアウトシフトを防止
- CSPへ必要なGoogle広告ドメインを追加
- ルームIDや利用者入力を広告リクエストのカスタム値にしない
- 広告読込失敗がタイマー機能を壊さないError Boundaryを用意
- Service Workerが広告応答をキャッシュしないことを確認

### `ads.txt`

承認後、AdSenseから示されたpublisher IDを使い、独自ドメイン直下の`/ads.txt`へ次の形式で配置する。

```text
google.com, pub-xxxxxxxxxxxxxxxx, DIRECT, f08c47fec0942fa0
```

実際の値はAdSense管理画面からコピーする。`ads.txt`はHTTP 200で取得でき、正しいpublisher IDを含む必要がある。

- [AdSense `ads.txt` FAQ](https://support.google.com/adsense/answer/9785052?hl=ja)
- [`ads.txt`をクロール可能にする](https://support.google.com/adsense/answer/7679060?hl=ja)

### Discord Activity

Discord ActivityはDiscordの音声チャンネルやDM内で動く。Googleは、私的コミュニケーションが主目的の画面や、利用者の注意が別の場所にある状況の広告を制限している。Pomodoro Together自体にチャット機能がなくても、Discord内埋め込みは解釈と審査の不確実性が高い。

したがって、初期版では次のようにする。

- Activity内ではAdSense scriptを読み込まない
- Discord連携は公式Web版への自然な利用者獲得として評価
- 広告収益はWebのトップ、記事、結果画面で得る
- 将来表示したい場合は、Googleへ確認できる資料と実際の画面を用意して再評価

## 集客方針

広告モデルでは、機能完成だけでは収益が発生しない。アプリを必要とする利用者へ継続的に届く導線が必要になる。

### Discord・LINE共有

- 共有文にサービス名、用途、参加URLを含める
- OGPに部屋名ではなく安全な一般情報を表示
- 招待された参加者が次回は自分でルームを作れる導線を置く
- 共有率と参加率を匿名集計

### 検索

- 「Discord ポモドーロ」「通話 作業 タイマー」「オンライン 自習室 タイマー」など、実際の問題に答える記事を作る
- 記事からタイマーをすぐ試せるようにする
- sitemap、robots、canonical、構造化データを整備
- Search Consoleで表示クエリ、クリック、インデックス状況を確認
- 他サイトの文章を再構成しただけの記事や大量自動生成記事は作らない

### 作者のポートフォリオ

- ココナラプロフィールから公式アプリへリンク
- 技術的な改善記録を公開
- GitHub READMEから本番サイトと解説記事へリンク
- Discordコミュニティ運営者へ、広告クリックではなく無料利用を案内

有料トラフィック交換、クリック依頼、報酬付き閲覧、広告を見ることを条件にした機能は使わない。

- [AdSenseとトラフィック交換プログラム](https://support.google.com/adsense/answer/1348729?hl=ja)

## 段階的ロードマップ

### Phase 0: 採算と基盤

- 独自ドメイン候補と商標衝突を確認
- 1秒ポーリングを5～10秒の適応同期へ改善
- 1セッションあたりのAPI・Redis使用量を計測
- 広告なしの現在値として離脱率、作成率、完了率を記録

### Phase 1: 審査可能なサイト

- トップの説明コンテンツを拡充
- 使い方、ポモドーロ入門、共同作業ガイド、FAQを作成
- Aboutを作者・設計・改善内容まで拡充
- プライバシー、外部送信、利用規約、問い合わせを作成
- 共通ナビゲーション、フッター、sitemap、robotsを追加
- Search Consoleと独自ドメインを設定

### Phase 2: AdSense申請

- 18歳以上の本人名義でAdSenseアカウントを作成
- 支払国・住所を正確に登録
- 既存AdSenseアカウントとの重複がないか確認
- サイト確認metaまたはscriptを設置
- Google CMPを設定
- サイト全体のポリシー・表示・モバイル確認
- 審査を申請。通常数日、場合によって2～4週間

### Phase 3: 限定広告

- 手動広告ユニットをトップと記事末尾に限定
- `ads.txt`を配置
- ルーム、エラー、Discord Activityを除外
- レイアウトシフト、操作ミス、速度を検証
- 2～4週間の収益、離脱、RPM、費用を確認

### Phase 4: 検証拡大

- 休憩中または手動結果画面の1枠をA/B検証
- 直接スポンサー枠の資料を作成
- 広告位置別の収益と離脱を比較
- 月次で収益、Vercel費、Redis費、ドメイン費を記録
- 利益が出ない配置は削除

## 継続・撤退基準

広告を付けたこと自体を成功とせず、次の式で判断する。

```text
広告粗利益 = 広告確定収益 - 広告によって増えた運営費

事業利益 =
  広告確定収益
  - Vercel・Redis・ドメイン・監視費
  - コンテンツ制作と保守に使った時間の評価額
```

継続条件の例:

- 広告導入でルーム作成率・完了率が大きく悪化しない
- 無効トラフィック警告がない
- API・Redis費用が広告収益を恒常的に上回らない
- コンテンツ検索流入と再訪が増えている
- プライバシー対応を維持できる

撤退・変更条件の例:

- 審査対策記事が本来のプロダクトと無関係になっている
- 広告収益より運用・法務・コンテンツ費用が継続して大きい
- 広告が集中体験やDiscord連携の価値を損なう
- 無効トラフィックを安全に制御できない

その場合も、広告モデル全体を捨てるのではなく、AdSenseからCookieを使わない直接スポンサー1枠へ変更する選択肢がある。

## 実装前に必要なユーザー側情報

AdSenseコードを本番へ入れる段階で、作者本人による次の準備が必要になる。

- 使用するGoogleアカウント
- 既存AdSenseアカウントの有無
- 支払先の国・氏名・住所
- 取得する独自ドメイン
- 広告収益の受取口座と税務情報
- 公開する運営者名・問い合わせ先
- 海外アクセスへ広告を配信するか
- パーソナライズ広告を使うか

パスワード、本人確認書類、銀行口座情報をGit、チャット、環境変数の共有文書へ保存しない。AdSense管理画面で本人が直接入力する。
